Location-Based Unique IDs for Fire Hydrants

A compact ArcPy workflow that creates and populates a Hydrant_ID field by deriving a repeatable identifier from each feature's stored latitude and longitude values.

Python ArcPy Enterprise GIS Data Management Automation

PROJECT OVERVIEW

Why this was necessary

The hydrant dataset needed a consistent way to identify individual features using information already stored with each record. Rather than manually assigning values, this script uses the Latitude and Longitude fields to generate a formatted, location-derived Hydrant_ID and writes the value directly back to the GIS dataset.

The result is a repeatable workflow that can process the feature class in one pass and reduce the amount of manual record maintenance required when assigning identifiers.

WORKFLOW

How the script works

  1. Connect to the data.
    The script sets the ArcPy workspace and identifies the hydrant feature class that will be processed.
  2. Prepare the ID field.
    It checks for a Hydrant_ID text field and creates the field when it does not already exist.
  3. Build the identifier.
    An UpdateCursor reads Latitude and Longitude, converts the values to strings, and combines selected coordinate digits into a formatted ID.
  4. Update each feature.
    The generated value is written to Hydrant_ID and the cursor saves the updated row.
Design note: Because the identifier is derived from selected coordinate digits, a production workflow should also validate the finished Hydrant_ID field for duplicates and account for records with missing coordinates or coordinate changes.

SOURCE CODE

Python / ArcPy implementation

Hydrants_UniqueIDs.py View source on GitHub 
import arcpy

# Set the workspace to the SDE connection
arcpy.env.workspace = r'Database Connections\wcva_default.sde\wcva.DBO.Utilities'

# Specify the layer name within the SDE
layer_name = 'wcva.DBO.hydrant'

# Add a new field for the Unique IDs if it doesn't exist already
if not arcpy.ListFields(layer_name, 'Hydrant_ID'):
    arcpy.AddField_management(
        layer_name,
        'Hydrant_ID',
        'TEXT',
        field_length=15
    )

# Update the Hydrant_ID field based on X and Y
with arcpy.da.UpdateCursor(
    layer_name,
    ['Latitude', 'Longitude', 'Hydrant_ID']
) as cursor:
    for row in cursor:
        lat_str = str(row[0])
        lon_str = str(row[1])

        # Ensure latitude and longitude strings are long enough for slicing
        if len(lat_str) > 6 and len(lon_str) > 7:
            unique_id = '{}{}{}{}-{}{}-{}{}{}{}-{}{}'.format(
                lat_str[1], lon_str[2], lat_str[2], lon_str[3],
                lat_str[3], lon_str[4],
                lat_str[4], lon_str[5], lat_str[5], lon_str[6],
                lat_str[6], lon_str[7]
            )

            if len(unique_id) > 15:
                unique_id = unique_id[:15]

            row[2] = unique_id
            cursor.updateRow(row)

print("Unique IDs generated successfully!")

NEXT STEPS

Potential enhancements

This workflow could be expanded with duplicate-ID validation, null-coordinate handling, logging, configurable input parameters, or packaging as an ArcGIS Pro script tool. Those additions would make the workflow easier to reuse against other point datasets while providing stronger validation and reporting.
