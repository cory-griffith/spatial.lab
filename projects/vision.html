Vision Real Estate & Parcel Integration

Developed a complex SQL query to retrieve current real estate information directly from the Vision database and associate it with the locality's parcel GIS data. This integration provides GIS users with ac cess to up-to-date property information while maintaining the parcel layer as the spatial foundation.

SQL Vision Joins

PROJECT OVERVIEW

Why this was necessary

This integration was necessary following the Real Estate Department's migration from the legacy CAMRA system to Vision. A new SQL query was developed to retrieve the relevant property information from Vision and align it with the existing fields associated with the locality's parcel data.

Without this integration, the parcel layer would contain geometry but lack much of the descriptive real estate information users rely on. The query restores that connection, allowing users to access current property information directly through the GIS parcel layer.

WORKFLOW

How it works

  1. Review the Vision data structure.
    Review the available Vision field documentation to understand how real estate information is stored and identify the attributes needed for GIS integration.
  2. Evaluate existing database views.
    Review the established SQL Server views to better understand existing table relationships, available fields, and how information is organized across the Real Estate database.
  3. Develop and test the SQL query.
    Query the necessary databases and progressively build the required dataset. Through iterative testing, refine joins, fields, and conditions until the results accurately represent the desired real estate information.
  4. Establish the parcel relationship.
    Identify a common key field between the Vision records and the authoritative parcel feature class, allowing the resulting real estate information to be reliably joined to its corresponding parcel geometry.
  5. Implement the production workflow.
    Finalize the query and establish a repeatable workflow that maintains the connection between current Vision records and GIS parcel data, providing users with access to up-to-date property information.
Design note:Utilize the vendor for questions as much as possible, as they have a better understanding of the database structure.

SOURCE QUERY

SQL Snippet

vision_ssms.sql 
USE ROViews_VA
GO

SELECT
    -- REAL_PROP_REALMAST fields
    rpr.REM_PID AS MRECNO,
    rpr.REM_GIS_ID AS GIS_ID,
    LTRIM(RTRIM(rpr.REM_ALT_PRCL_ID)) AS MMAP,
    rpr.REM_LEGAL_AREA AS [MACRE#],
    rpr.REM_PARCEL_STATUS AS PARSTAT,
    rpr.REM_USRFLD_DESC AS MMAGCD,

    NULLIF(
        NULLIF(
            LTRIM(RTRIM(
                CASE
                    WHEN sh.book_clean LIKE 'WF%'
                         AND sh.page_clean IS NOT NULL
                    THEN
                        'WF-'
                        + RIGHT(sh.book_clean, 2)
                        + REPLICATE(
                            '0',
                            CASE
                                WHEN LEN(sh.page_clean) >= 5 THEN 0
                                ELSE 5 - LEN(sh.page_clean)
                            END
                        )
                        + sh.page_clean
                    ELSE rps.SLH_USER3
                END
            )),
            ''
        ),
        '0'
    ) AS MWPAGE,

    FORMAT(rps.SLH_SALE_DATE, 'MM/dd/yyyy') AS SALEDATE,

COALESCE(cdm.CNS_STORIES, cdu.CNS_STORIES, com.CNS_STORIES, res.CNS_STORIES) AS [MSTOR#],
COALESCE(res.CNS_USRFLD_81_DESC, com.CNS_USRFLD_203_DESC) AS MGART,
COALESCE(res.CNS_USRFLD_106_DESC, com.CNS_USRFLD_106_DESC) AS MGART2,

FROM WarrencountyVA10124.REAL_PROP_REALMAST rpr

LEFT JOIN WarrencountyVA10124.REAL_PROP_ADDRESS rpa
    ON rpr.REM_PID = rpa.ADR_PID

LEFT JOIN WarrencountyVA10124.REAL_PROP_CONSTRCDM cdm
    ON rpb.BLD_PID = cdm.CNS_PID
   AND rpb.BLD_BID = cdm.CNS_BID

WHERE rpr.REM_PARCEL_STATUS = 'A'
  AND rps.SLH_CURRENT_OWNER = 1
  AND rpl.LND_LINE_NUM = 1
  AND rpl.LND_BLDG_NUM = 1

ORDER BY rpr.REM_PID ASC;
