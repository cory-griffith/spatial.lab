Implementation of a Computer Aided Dispatching Software

Supporting local emergency agencies by configuring local data to the standards desired by the CAD system.

NG9-1-1 Computer Aided Dispatching ArcGIS Server Python

PROJECT OVERVIEW

Why this was necessary

This project was necessary to ensure that authoritative GIS data could be reliably integrated into the locality's Computer Aided Dispatch (CAD) system, which supports critical emergency response operations. The CAD environment relies heavily on GIS and requires specific datasets, schemas, and formatting to function correctly.

Because the CAD server operates outside of the internal GIS network, I developed a series of Python workflows to prepare and package the required GIS data for transfer. Once moved to the CAD environment, additional automation truncates and reloads the existing datasets, processes the updated data, and prepares the associated services for publication. This created a repeatable update process while maintaining separation between the internal GIS and CAD environments.

WORKFLOW

How it works

  1. Maintain authoritative GIS data.
    Ensure the source road, address, and supporting GIS datasets are properly maintained and current before beginning the CAD update process.
  2. Format critical Roads and Addresses.
    Run the two Python formatting scripts developed from the CAD implementation documentation. These scripts transform the authoritative road and address data into the required schemas and formats expected by the CAD system.
  3. Package supporting GIS data.
    Run the packaging script to collect the additional non-critical GIS layers required by the CAD environment and consolidate them into a file geodatabase for transfer.
  4. Transfer the GIS package.
    Manually transfer the completed data package from the internal GIS environment to the external CAD server, maintaining separation between the two environments.
  5. Truncate and reload CAD datasets.
    Execute the automated batch workflow on the CAD server. The associated Python scripts truncate the existing feature data and append the newly prepared records from the transferred geodatabase.
  6. Run GIS processing models.
    Execute the required ModelBuilder workflows to perform the remaining processing and prepare the refreshed datasets for use by the CAD applications and services.
  7. Publish updated GIS services.
    Publish or overwrite the required GIS services so the CAD environment can consume the newly processed and updated authoritative data.

RESULT

Outcome and next steps

A future improvement would be to host the required GIS data within an enterprise geodatabase on the same network as the CAD environment. This would reduce the dependency on manually transferring file geodatabases between networks and create a more direct and maintainable update workflow.

The current process includes safeguards, including archived working datasets, to support recovery if an issue occurs during an update. However, reducing intermediate data transfers would further improve reliability and simplify long-term maintenance.
