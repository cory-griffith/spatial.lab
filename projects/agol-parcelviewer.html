Development of a public facing web applicaion through ESRI's ArcGIS Online platform.

ArcGIS Online Arcade Automation Web Experience Builder

PROJECT OVERVIEW

Why this was necessary

Due to IT security requirements and limited GIS infrastructure, hosting a public-facing parcel viewer internally was not practical. I developed a cloud-hosted solution using ArcGIS Online, eliminating reliance on a third-party consultant to host/manage, while providing a more cost-effective approach.

Bringing the application under GIS management gives the organization greater control over its public-facing data and allows updates to be published more quickly. This provides the public with a more current, reliable, and maintainable GIS resource.

MORE INFORMATION

Details

  1. ArcGIS Online Hosted
    Utilizies under 130 credits a month from storage.
  2. Scripting
    Developed a Python script to automatically pull specific layers from our database.
  3. Uploads
    Output of script is a GDB, which I manually overwrite the source layers in ArcGIS Online.
Design note: Once schema is established within AGOL, the GDBs must maintain this or uploads will not work. Also, ensure data within AGOL is non-editable.

RESULT

Outcome and next steps

The implementation of this application has provided the locality with greater control over its public-facing GIS while reducing budgetary pressure on the department. Application maintenance and data updates are now handled in-house. Future improvements will include additional parcel attributes and continued enhancements to the custom parcel pop-up experience.

CODE WALKTHROUGH

How the ArcGIS Online update workflow works

Two Python workflows prepare the GIS data used by the public parcel viewer. AGOL_RegUpdates builds and processes the primary public-facing datasets, while AGOL_DesignerUpdates packages additional supporting layers used by the application.

AGOL_RegUpdates — Create a Fresh Update Package 
delete_file_if_exists(out_zip)
          delete_dir_if_exists(out_gdb)

          arcpy.CreateFileGDB_management(
              OUT_FOLDER,
              OUT_GDB_NAME
          )

          arcpy.env.workspace = out_gdb
01

Start with a clean export environment

Each update begins by removing the previous output package and creating a new file geodatabase. This ensures the upload is built entirely from the latest authoritative GIS data rather than carrying forward outdated records.

AGOL_RegUpdates — Extract & Simplify GIS Layers 
arcpy.CopyFeatures_management(
              e911address_sde,
              os.path.join(out_gdb, "e911address")
          )

          arcpy.CopyFeatures_management(
              e911roads_sde,
              roads_local
          )

          dissolve_fields = [
              "STREET",

              "CLASS",
              "SPEED",
              "ONEWAY"
          ]

          arcpy.Dissolve_management(
              roads_local,

02

Extract and optimize public GIS data

Authoritative datasets are copied from the enterprise GIS environment into the temporary update geodatabase. Certain layers, such as road centerlines, are simplified through processing so the public-facing version contains the information needed by the application without unnecessary complexity.

AGOL_RegUpdates — Build the Public Parcel Layer 
parcels_key = "TPIN"
          vision_key = "TPIN"

          arcpy.JoinField_management(

03

Enrich the parcel dataset

The parcel layer is enhanced with current real estate information using a common parcel identifier. A spatial join then adds additional geographic information, such as school district attribution, before the final public parcel layer is created.

calculate_maspin_from_tmegid(

04

Clean and package the update

Before delivery, the parcel output is cleaned and standardized for public use. Temporary information is removed, selected values are reformatted, workspace locks are released, and the completed file geodatabase is compressed into a ZIP package ready for the ArcGIS Online update process.
